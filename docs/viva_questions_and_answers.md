## Section 1: Java 21 LTS & Spring Boot 3 Architecture

### Q1: What makes Java 21 LTS suitable for high-throughput enterprise systems?
**Answer**: Java 21 introduces several enterprise-grade features:
- **Virtual Threads (Project Loom)**: Lightweight threads managed by the JVM that reduce the memory footprint per thread from ~1MB to a few kilobytes, enabling tens of thousands of concurrent I/O operations without thread pool exhaustion.
- **Record Patterns & Pattern Matching for `switch`**: Facilitates immutable Data Transfer Objects (DTOs) with concise deconstruction and compile-time type safety.
- **Sequenced Collections**: Provides standard access patterns for first, last, and reversed elements (`getFirst()`, `getLast()`).
- **Generational ZGC (Z Garbage Collector)**: Achieves sub-millisecond maximum pause times regardless of heap size, critical for real-time CRM dashboards.

### Q2: Why use Spring JDBC (`JdbcTemplate` / `SimpleJdbcCall`) instead of Spring Data JPA/Hibernate in this architecture?
**Answer**:
1. **Direct PL/SQL Package Invocation**: Enterprise Oracle systems rely on PL/SQL packages for business logic, transactional integrity, and batch calculations. `SimpleJdbcCall` maps IN and OUT parameters directly to database stored procedures with zero ORM overhead.
2. **Explicit Concurrency Control**: Hibernate often obscures SQL generation, making fine-grained control over `SELECT ... FOR UPDATE` row locks difficult. Direct SQL and PL/SQL calls ensure transparent lock acquisition and transaction management.
3. **Reduced Memory & N+1 Overhead**: Eliminates entity dirty checking, first-level session caching, and accidental N+1 query execution on complex enterprise joins.

### Q3: How is authentication and role-based access control (RBAC) enforced in Spring Security?
**Answer**:
Spring Security intercepts incoming HTTP requests through a chain of servlet filters (`SecurityFilterChain`).
1. The `SecurityContextHolder` maintains the active `Authentication` object, which contains the principal's username and granted authorities (e.g. `ROLE_SALES_MANAGER`, `ROLE_FINANCE_TEAM`).
2. Endpoints are protected using `.requestMatchers("/api/admin/**").hasRole("ADMIN")` or method-level annotations like `@PreAuthorize("hasAuthority('ROLE_SUPER_ADMIN')")`.
3. In our system, the demo role-switching feature dynamically updates the `SecurityContext` within the current session, allowing instant evaluation of different user roles.

## Section 2: Oracle Database 26ai & Relational Design

### Q4: Why did we normalize the database schema into 27 tables in Third Normal Form (3NF)?
**Answer**:
Third Normal Form ensures that:
1. Every non-key attribute depends strictly on the primary key, the whole primary key, and nothing but the primary key (no transitive dependencies).
2. Prevents data anomalies:
   - **Insertion Anomaly**: We can register a Product without needing an active purchase order.
   - **Update Anomaly**: If a customer changes their billing address, we update a single record in `CUSTOMERS` rather than thousands of historical order rows.
   - **Deletion Anomaly**: Deleting an order does not accidentally delete the customer or the purchased product catalog entry.

### Q5: How do identity columns differ from traditional Oracle sequences?
**Answer**:
In older Oracle versions (prior to 12c), primary keys required creating an independent sequence (`CREATE SEQUENCE cust_seq`) and a `BEFORE INSERT` trigger to populate the column.  
In Oracle 26ai, `GENERATED BY DEFAULT AS IDENTITY` automatically associates an internal sequence directly with the column. However, if explicit IDs are manually inserted (e.g. during seed migration), the internal sequence must be restarted using:
```sql
ALTER TABLE table_name MODIFY column_name GENERATED BY DEFAULT AS IDENTITY (RESTART START WITH new_val);
```

### Q6: What indexing strategies were implemented to optimize query performance?
**Answer**:
1. **Unique Indexes**: Automatically created on primary keys and unique identifiers (`sku`, `order_number`, `invoice_number`, `idempotency_key`, `email`).
2. **Foreign Key B-Tree Indexes**: Created on child foreign keys (`customer_id` on `ORDERS`, `assigned_to` on `OPPORTUNITIES`) to eliminate full table locks during parent record updates and speed up joins.
3. **Composite Indexes**: Used for multi-column search predicates, such as `(stage, assigned_to)` on `OPPORTUNITIES` to accelerate Kanban board aggregation.
4. **Functional / Normalized Indexes**: Phone numbers are stored with a clean normalized digits column (`normalized_phone`) indexed for fast duplicate checking.

## Section 3: Oracle PL/SQL Engineering

### Q7: Why encapsulate business logic in PL/SQL packages rather than individual standalone procedures?
**Answer**:
- **Namespace Management & Modularity**: Packages group logically related procedures, functions, types, and constants under a single cohesive specification (e.g. `CRM_INVENTORY_PKG`, `CRM_FINANCE_PKG`).
- **Information Hiding**: The package body can contain private helper functions and variables invisible to external callers.
- **Performance (Session Caching)**: When any procedure in a package is called for the first time, Oracle loads the entire package into the Shared Pool in memory (SGA), making subsequent calls faster without disk I/O.
- **Dependency Minimization**: Changing a package body does not invalidate dependent database objects as long as the public package specification remains unchanged.

### Q8: When should you use PL/SQL Packages vs Database Triggers?
**Answer**:
- **Triggers**: Best suited for transparent, mandatory, and cross-cutting rules that must apply regardless of who executes the SQL (e.g. auto-populating audit timestamps, preventing direct deletes on financial ledgers, or logging security anomalies).
- **Packages**: Best suited for explicit transactional workflows that require input parameters, explicit confirmation, return codes, and multi-step orchestration (e.g. `CONVERT_LEAD`, `CONFIRM_ORDER`, `RECORD_PAYMENT`). Overusing triggers can cause hidden side-effects and mutating table errors (`ORA-04091`).

### Q9: Explain how `CRM_CUSTOMER_PKG.DETECT_DUPLICATE_CUSTOMER` prevents data duplication.
**Answer**:
Before inserting a new customer record, the application normalizes the submitted phone string by stripping non-digit characters and country code prefixes. The procedure then performs a two-tier duplicate check:
1. Exact match on normalized email: `LOWER(email) = LOWER(p_email)`.
2. Match on normalized phone number: `normalized_phone = v_norm_phone`.
If a match is found, the procedure returns `p_is_duplicate = 1` and provides the existing `p_existing_customer_id`, allowing the system to update the existing profile rather than creating a duplicate record.

## Section 4: Concurrency, Transactions & ACID Guarantees

### Q10: How does the system prevent negative inventory balances during simultaneous orders?
**Answer**:
The system uses **Pessimistic Concurrency Control** via `SELECT ... FOR UPDATE`:
```sql
SELECT available_stock, reserved_stock
  INTO v_avail, v_res
  FROM INVENTORY
 WHERE product_id = p_product_id
   FOR UPDATE;
```
1. When Thread A requests stock reservation, Oracle places an exclusive row-level lock on that product's inventory record.
2. If Thread B attempts to reserve stock for the same product simultaneously, it blocks until Thread A commits or rolls back.
3. Thread A checks if `v_avail >= p_quantity`. If sufficient, it decrements `available_stock` and commits.
4. Thread B then acquires the lock and reads the updated `available_stock`, preventing race conditions and negative inventory balances.

### Q11: What are ACID properties and how does this application maintain them?
**Answer**:
- **Atomicity**: In `CRM_ORDER_PKG.CONFIRM_ORDER`, order status update, invoice creation, and shipping queue dispatch succeed together or roll back entirely.
- **Consistency**: Database CHECK constraints (`min_selling_price >= cost_price`, `available_stock >= 0`) enforce business invariants at all times.
- **Isolation**: Oracle's default Read Committed isolation level combined with explicit row locks (`FOR UPDATE`) prevents dirty reads and lost updates.
- **Durability**: Committed transactions are written to the database redo log buffers and flushed to disk.

### Q12: How is Payment Idempotency achieved in this architecture?
**Answer**:
When a client initiates a payment, it generates a unique UUID `idempotencyKey`.  
1. In `CRM_FINANCE_PKG.RECORD_PAYMENT`, an insert is performed into the `PAYMENTS` table, which contains a `UNIQUE` constraint on `idempotency_key`.
2. If network retries resend the same payload, the second insert violates `uq_payment_idempotency` and raises `ORA-00001`.
3. The exception handler catches this violation and returns a distinct conflict status without applying a duplicate balance deduction to the invoice.

## Section 5: Application Security & Enterprise Governance

### Q13: How does the system defend against SQL Injection?
**Answer**:
1. **Parameterized Queries**: All dynamic queries in Spring Boot use `JdbcTemplate` with bind variables (`?`), ensuring user inputs are treated as literal values rather than executable SQL syntax.
2. **PL/SQL Stored Procedures**: Parameters passed to `SimpleJdbcCall` are bound as typed parameters (`Types.NUMERIC`, `Types.VARCHAR`), preventing SQL injection at the database engine level.

### Q14: How does the Commission Calculation Engine preserve historical audit accuracy?
**Answer**:
Commission policies change over time (e.g. tier percentages increase or decrease). To prevent recalculating historical sales at new rates:
1. `COMMISSION_RULES` maintains a `rule_version` column.
2. When a sale qualifies for commission, `COMMISSION_RECORDS` stores both the calculated payout and the exact `rule_version` applied at calculation time.
3. If an administrator alters a commission rule, the system creates a new version, leaving historical vouchers untouched.

### Q15: What is the purpose of Departmental Work Queues?
**Answer**:
Departmental Work Queues decouple cross-functional business processes:
- When an order is confirmed, the system enqueues a ticket into the `SHIPPING` queue for warehouse staff to pack and ship.
- When an invoice has an overdue balance, a ticket is routed to the `FINANCE` queue for collection follow-up.
- Role-based permissions ensure departments only process tickets within their domain, improving operational focus and accountability.
